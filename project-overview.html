01Ringkasan eksekutif

VoterScope Demo adalah aplikasi web full-stack untuk manajemen data pemilih pada konteks administratif Indonesia. Aplikasi ini menangani entitas khas administrasi pemilih: NIK (Nomor Induk Kependudukan), TPS (Tempat Pemungutan Suara), dan hierarki wilayah resmi Kemendagri dari tingkat provinsi sampai kelurahan. Seluruh data dibuat oleh skrip seed dan bersifat sintetis; proyek ini memang dirancang sebagai portofolio dan alat edukasi, bukan sistem produksi.

Analisis kode menemukan proyek yang sudah selesai dalam ruang lingkup demonya. Sepuluh fitur inti terpasang penuh dan terhubung ke data nyata melalui Prisma dan SQLite, tanpa satu pun handler yang di-mock saat runtime. Pencarian pada seluruh source tidak menemukan penanda TODO, FIXME, atau blok kode yang dikomentari. Fokus terkuat proyek ada di lapisan keamanan dan tata kelola: enkripsi NIK, blind indexing, RBAC hierarkis lima tingkat, serta jejak audit yang lengkap dengan ekspor kepatuhan.

Pekerjaan yang tersisa bukan fitur, melainkan kesiapan operasional. Jalur upgrade ke produksi (PostgreSQL, Redis, KMS, OAuth2/OIDC) sudah didokumentasikan di docs/future-production-upgrade.md tetapi belum dieksekusi. Repositori berisi dua commit, pohon kerja bersih, dan belum memiliki pipeline CI.

04Arsitektur

Kode berada di root repositori tanpa folder src/, mengikuti struktur App Router Next.js 16.

voterscope-demo/
├── proxy.ts              Gerbang auth + security headers (pengganti middleware.ts)
├── app/                  37 file: halaman App Router + 15 route handler API
│   ├── api/              auth, voters, users, profile, territories, dashboard, audit
│   ├── dashboard/        View terautentikasi: voters, users, audit, profile
│   ├── login/            Form login + pemilih persona demo
│   └── globals.css       Token desain Catppuccin (594 baris)
├── components/           6 komponen: tabel, form, filter, chart, theme toggle
├── lib/                  15 modul logika bisnis (±2.000 baris)
│   ├── authorization/    RBAC hierarkis + guard anti-IDOR (319 baris)
│   ├── security/         Enkripsi NIK + rate limiter
│   ├── territory/        Kodewilayah + snapshot district offline (761 KB)
│   └── validation/       Skema Zod bersama
├── prisma/               Schema (7 model), 1 migrasi, seed 100 pemilih
├── tests/                unit/ (9 suite Vitest) + e2e/ (3 spesifikasi Playwright)
└── docs/                 8 dokumen teknis + 4 screenshot

Alur satu permintaan tulis (misal tambah pemilih)

  1. proxy.ts memeriksa sesi cookie, memblokir akses tanpa login (redirect ke /login), dan menambahkan security headers.
  2. Client mengirim mutasi ke route handler di app/api/; payload divalidasi ulang dengan skema Zod di sisi server.
  3. Guard RBAC memeriksa scope hierarkis; filter wilayah dari client ditimpa dengan scope resmi dari sesi, sehingga tidak bisa dilewati.
  4. NIK dienkripsi AES-256-GCM, blind index HMAC-SHA256 dihitung untuk deteksi duplikat, dan validasi hierarki wilayah dijalankan.
  5. Setiap operasi penting menulis baris audit (aktor, aksi, IP, user agent, hasil), lalu Prisma mengeksekusi perubahan ke SQLite.

Data wilayah bersifat offline-first: lib/territory/ menyimpan snapshot 38 provinsi dan 514 kabupaten/kota plus 761 KB district pra-muat; satu-satunya kontak API eksternal terjadi saat persiapan data, bukan saat runtime.

05Model data

Tujuh model Prisma di prisma/schema.prisma, dipetakan ke tabel snake_case dengan indeks lengkap.

Hierarki wilayah: Province, Kabupaten, Kecamatan, Kelurahan

Empat model dengan kode resmi Kemendagri yang unik per tingkat, saling terhubung lewat foreign key. Menyediakan 38 provinsi dan 514 kabupaten/kota, plus district pra-muat untuk mode offline.

User

Username dan email unik, passwordHash Argon2id, role sebagai string dengan enam nilai yang divalidasi di lapisan aplikasi, dan empat foreign key scope wilayah opsional sesuai jabatan.

Voter

NIK tidak pernah disimpan sebagai teks biasa: nikEncrypted (AES-256-GCM) plus nikLookupHash unik (HMAC-SHA256) sebagai blind index. Atribut demografi, TPS, status (ACTIVE, NEEDS_REVIEW, ARCHIVED), archivedAt untuk soft delete, relasi created/updated-by, dan sekitar 11 indeks.

AuditLog

Aktor, aksi, tipe dan target resource, timestamp, IP, user agent, hasil, serta metadata JSON. Menjadi dasar peninjau kepatuhan dan ekspor CSV/JSON.

Seed

prisma/seed.ts (390 baris) membuat 6 akun demo, satu per peran dengan sandi bersama Demo@12345, dan 100 pemilih sintetis memakai kode wilayah asli Jawa Barat (32, 3201, Cibinong, Karadenan). Database prisma/dev.db (1,2 MB) ada di lokal dan dikecualikan dari git.

07Keamanan

Keamanan adalah showcase utama proyek ini. Semua mekanisme berikut terpasang di kode, bukan hanya rencana.

Hash kata sandi

Argon2id dengan parameter OWASP (m=65536, t=3, p=4). Saat username tidak ditemukan, verifikasi tetap dijalankan terhadap dummy hash agar waktu respons seragam dan enumerasi user sulit.

Sesi

iron-session: cookie http-only tersegel AES-256-GCM dengan TTL 8 jam, tanpa state sesi di server. proxy.ts memvalidasi tiap permintaan sebelum halaman tampil.

Perlindungan NIK

AES-256-GCM dengan IV 96-bit unik dan auth tag 128-bit. Blind index HMAC-SHA256 memungkinkan deteksi duplikat tanpa dekripsi. NIK tampil tersamar (3201************) secara default; dekripsi dilakukan saat diminta dan selalu tercatat di audit.

RBAC hierarkis 5 tingkat

Nasional, Provinsi, Kabupaten, Kecamatan, Kelurahan. Server menimpa filter client dengan scope resmi; guard anti-IDOR memeriksa eskalasi horizontal dan vertikal, dan percobaan dicatat sebagai ACCESS_DENIED atau IDOR_ATTEMPT_SCOPE_MISMATCH.

Anti-penyalahgunaan

Rate limiter sliding-window: login 10 percobaan per 15 menit per IP, lookup NIK 20 permintaan per menit. Implementasi in-memory dan memang hanya untuk satu proses (lihat isu nomor 3).

Header dan jejak audit

CSP ketat, X-Frame-Options: DENY, proteksi MIME-sniffing. Audit log menangkap aktor, IP, user agent, aksi, target, hasil, dan metadata JSON untuk semua operasi penting.

09Isu yang diketahui

Daftar temuan analisis, diurutkan dari yang paling berdampak. Semua referensi file sudah diverifikasi langsung.

  1. 20 dependensi tak terpakai di package.json: 14 paket @radix-ui/react-*, plus lucide-react, jose, nanoid, date-fns, class-variance-authority, dan devDep @types/better-sqlite3. Tidak berdampak ke runtime, tetapi memperlambat instalasi dan menyesatkan pembaca audit.
  2. Fallback secret hardcode saat env hilang: proxy.ts:16 dan lib/auth/session.ts:19 memakai sandi sesi dev; prisma/seed.ts:28-32 menetapkan kunci NIK dev. Wajar untuk demo lokal, berbahaya jika pola ini terbawa ke produksi.
  3. Rate limiter in-memory (lib/security/rate-limit.ts) hanya berlaku per proses; produksi butuh penyimpanan bersama seperti Redis.
  4. Ekspor audit dibatasi 1.000 baris dan tidak mengikuti filter aktif di peninjau, sehingga hasil ekspor bisa berbeda dari yang dilihat peninjaunya.
  5. Duplikasi logika agregasi dashboard antara app/dashboard/page.tsx dan app/api/dashboard/stats/route.ts; perubahan rumus harus dilakukan di dua tempat.
  6. Error diam-diam di direktori pemilih: app/dashboard/voters/VotersClient.tsx:55 hanya memanggil console.error saat fetch gagal, sehingga tabel tampak kosong tanpa pesan kesalahan.
  7. Latar not-found hardcode gelap: app/not-found.tsx:7 memakai hsl(222 47% 6%) dan mengabaikan tema Latte.
  8. CSP masih longgar: proxy.ts:105 mengizinkan 'unsafe-inline' dan 'unsafe-eval' untuk script; dipahami sebagai kebutuhan Next dev, tetapi perlu diperketat untuk produksi.
  9. Tidak ada CI (folder .github/ tidak ada); klaim kualitas di README hanya bisa diverifikasi manual.
  10. Angka test di FINAL_AUDIT.md kedaluwarsa (123, aktual 142); lihat bagian Pengujian.

10Rekomendasi

  1. Bersihkan dependensi mati. Hapus 20 paket tak terpakai, lalu jalankan ulang build dan test untuk memastikan tidak ada impor tersembunyi.
  2. Tambahkan CI minimal. GitHub Actions dengan lint, typecheck, vitest, dan build pada tiap push; murah dan langsung menaikkan kredibilitas portofolio.
  3. Perbaiki dua isu UX kecil. Banner kesalahan pada VotersClient dan latar not-found yang mengikuti tema aktif.
  4. Segarkan FINAL_AUDIT.md. Perbarui angka test dan tanggal verifikasi agar dokumen audit konsisten dengan kenyataan.
  5. Selaraskan ekspor audit. Terapkan filter aktif peninjau pada ekspor, atau tampilkan batas 1.000 baris secara eksplisit di UI.
  6. Jika menuju produksi: eksekusi docs/future-production-upgrade.md secara bertahap, yaitu PostgreSQL, Redis untuk rate limit, KMS untuk kunci NIK, OAuth2/OIDC, pengerasan CSP, dan ambang coverage di Vitest.
