# VoterScope Demo — Assumptions

> This document records all assumptions made during the design and development of VoterScope Demo.

---

## 1. Purpose

VoterScope Demo is a **portfolio/demo application**.

It is designed to demonstrate:

- Hierarchical role-based access control (RBAC)
- Administrative scope enforcement
- Voter record CRUD with audit logging
- Security-aware architecture
- Modern full-stack TypeScript development

**This application does not process, store, or transmit real voter data.**

All data is synthetic and generated deterministically by the seed script.

---

## 2. Data Assumptions

### 2.1 Synthetic Data Only

ALL voter records in this system are synthetic.

The seed script generates fictitious names, dates of birth, addresses, and NIK-like identifiers.

No real personal data is used at any stage.

### 2.2 Synthetic NIK

NIK-like identifiers generated by the seed script do not correspond to real Indonesian KTP numbers.

They are 16-digit strings used solely to demonstrate encryption and duplicate-detection architecture.

**Code comment in seed.ts:**
```typescript
// ALL IDENTIFIER VALUES ARE SYNTHETIC DEMO DATA.
```

### 2.3 Administrative Hierarchy

The administrative hierarchy (Province → Kabupaten → Kecamatan → Kelurahan) uses fictional names:

- Province: Demo Province
- Kabupaten: Demo Kabupaten Alpha, Demo Kabupaten Beta
- Kecamatan: Demo Kecamatan 1–3
- Kelurahan: Demo Kelurahan A–F

These names have no correspondence to real Indonesian administrative regions.

## 3. Technology Assumptions

### 3.1 SQLite for Demo

SQLite was chosen because:

- Zero installation required
- Works cross-platform (Windows, macOS, Linux)
- Perfect for a local demo
- Prisma provides full ORM support

Production deployments would use PostgreSQL. See `docs/future-production-upgrade.md`.

### 3.2 iron-session for Sessions

iron-session provides encrypted, signed, HTTP-only cookie sessions without requiring Redis or a separate session store.

Suitable for a single-server demo. Not suitable for horizontally-scaled production.

### 3.3 In-Memory Rate Limiting

The rate limiter uses a simple in-memory Map.

This resets on server restart and does not work across multiple Node.js processes.

Production must use Redis-backed rate limiting.

### 3.4 Argon2id for Passwords

Argon2id is the recommended password hashing algorithm. The `argon2` npm package wraps the reference C implementation.

### 3.5 AES-256-GCM for NIK Encryption

AES-256-GCM provides authenticated encryption — it guarantees both confidentiality and integrity.

IV is randomly generated per encryption. Auth tags prevent ciphertext tampering.

---

## 4. Authorization Assumptions

### 4.1 Server-Side Is Authoritative

The frontend NEVER makes final access control decisions. All authorization is enforced server-side.

### 4.2 Role Hierarchy

A higher-level admin can manage users at lower levels, but cannot escalate their own privileges.

### 4.3 Scope Isolation

A user can only access data within their assigned administrative scope.

Accessing data outside scope returns HTTP 403 regardless of URL manipulation.

---

## 5. Security Assumptions

### 5.1 Development Secrets

The `.env` file contains development-only placeholder secrets.

In production, all secrets must be rotated and stored in a secure secrets manager (e.g., AWS KMS, HashiCorp Vault).

### 5.2 No WAF

No Web Application Firewall is configured for this local demo.

Production deployments require a WAF (e.g., AWS WAF, Cloudflare).

### 5.3 No Penetration Testing

This demo has not undergone formal penetration testing or security audit.

### 5.4 TLS Not Enforced Locally

TLS is enforced in production mode via HSTS headers. Local development runs on HTTP.

---

## 6. Not Implemented (Intentionally)

The following features are intentionally out of scope for the demo:

- Real-time notifications
- File/document uploads
- Print/export to PDF
- Multi-factor authentication (MFA)
- OIDC / enterprise SSO
- Email verification
- Two-factor login
- Advanced analytics (regression, forecasting)
- Political preference tracking (explicitly prohibited — see prompt)
- Production infrastructure (Docker Compose, K8s, etc.)

---

## 7. Compliance Disclaimer

This application has not been evaluated for compliance with:

- Undang-Undang Perlindungan Data Pribadi (UU PDP)
- GDPR or any equivalent privacy regulation
- KPU technical specifications
- Any government system security standard

It is purely a technical portfolio demonstration.
